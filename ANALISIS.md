*¿Qué problemas tenía el proyecto sin Git?*
Sin Git era más difícil controlar los cambios realizados en el proyecto. Podían perderse archivos, sobrescribirse cambios de otros compañeros y era complicado saber quién había modificado algo o recuperar una versión anterior.

*¿Cómo ayudó Git a organizar el trabajo?*
Git permitió guardar los cambios de manera ordenada mediante commits. Así, cada modificación quedaba registrada y era posible saber qué se cambió, cuándo se hizo y quién lo hizo.

*¿Qué ventajas aporta el uso de ramas?*
Las ramas permiten trabajar en diferentes funciones o partes del proyecto sin afectar directamente al código principal. También facilitan que varios integrantes trabajen al mismo tiempo y luego integren sus cambios.

*¿Por qué es importante el historial de cambios?*
Porque permite conocer la evolución del proyecto y recuperar versiones anteriores si ocurre algún error. Además, ayuda a identificar cuándo y por qué se realizó una modificación.

*¿Cómo se relaciona esto con el trabajo en equipo real?*
Git facilita la colaboración entre varias personas, ya que cada integrante puede trabajar en sus propias tareas y después compartir e integrar sus cambios. Esto reduce conflictos, mantiene el proyecto organizado y hace más eficiente el trabajo en equipo.
